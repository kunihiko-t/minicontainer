# MiniContainer v1.2.0

v1.2.0はv1 MiniBundleの監視起動と、保存結果への再接続を提供する互換的なminor releaseである。既に統合した記録基盤と監視CLI、通常umaskでのstate permission修正を含む。標準MiniOS kernelは `086f2e3fa54f751cd28c5fcd2bed205830bd2934` を維持する。

## 追加した操作

`minictr start` はguest READYを確認した後に保存記録IDを返す。起動commandの0はREADY確認であり、guestの正常終了を意味しない。監視役が共有stdout/stderrをowner専用logに保存し、stdinにはEOFを送る。

別terminalから `minictr status [--wait] ID` でrunning/exited/failed/unknownと終了codeを確認できる。waitはQEMUの実status確認・wait/reap・payload/state回収後に保存されたguest codeを返す。待機期限切れやqueryのsignalは実行自体を停止しない。

停止は現在のidentityと一致するINSTANCE列を使い、既存ps/stopで行う。監視役喪失や旧stateはunknownとし、成功を推測しない。PID再利用や別runへのstate置換では停止用リンクを表示しない。

詳細は [v1監視起動の契約](https://github.com/kunihiko-t/minicontainer/blob/v1.2.0/docs/reference/supervised-v1.md) を参照する。

## 互換性と修正

旧run/detach/ps/stop、manifest v1/v2のforeground、boot/Ready wire ABI 1.2、minios-abi-v0.2.0、bundle digest、instance state v1、OCI media typeを維持する。既存kernelやbundleの再構築・移行を要求しない。CLIの追加は互換変更で、既存commandのstdout・終了code契約を変えない。

通常umask0022でstateが0644となり、安全な再接続検証に拒否される不具合を修正した。作成時から0600に限定し、読取側のowner/permission/symlink/identity検証は緩めない。保存snapshot形式も維持する。

## 検証と制限

通常の全18検査と実QEMUでhello/echo、EOF、stdout/stderr、42、短命READY、再接続、timeout、signal、stop競合、監視役喪失と手動回収、process/state/payload cleanupを検査する。umask0022/0000/0077と公開permission拒否の回帰test、Ubuntu/macOS host CIを含む。archive内CLIのstart/statusとchecksumも検査する。

v2 detachedは未対応で、v2の監視起動は副作用前に拒否する。v2の既存foregroundは引き続き使える。task別I/O、log表示CLI、保存記録の自動retention、サービス登録は追加しない。SIGKILLやhost電源喪失後の自動QEMU回収は保証せず、既存ps/stopで回収する。

macOS CIはhost検査とmacOS配布buildを行う。macOS実機QEMUと物理FPGAは未確認である。配布物はLinux x86_64とmacOS arm64で、checksumとprovenanceで検証する。
