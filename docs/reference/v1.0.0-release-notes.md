# MiniContainer v1.0.0 release notes

v1.0.0は、学習用マイクロVMランタイムとしての公開契約を固定した版である。
v0.1.0で計画したv0.2.0からv1.0.0までの全マイルストーンをこの版にまとめ、中間のtagは打っていない。
各契約の保証と検証根拠は[公開契約の監査表](public-contract.md)、変更時の解釈基準は[互換性と移行の方針](compatibility.md)が正である。

## 破壊的変更

利用者の作業を必要とする変更は、Guest ABIのpinの更新だけである。

- Guest ABIのpinを`minios-abi-v0.1.1`から`minios-abi-v0.2.0`へ、配布kernelの固定revisionを`9be99255a59d58d19db25b835af0e28a8d2a4036`から`4865f9be97a6cdcd77c71e36b1ba426b49bd73d7`へ上げた。
  ABI majorは1のまま、minorが0から2へ進んだ。
  v0.1.0のkernelで動いたguest ELFとbundleはv1.0.0のhostでもそのまま動く。
  逆に、v1.0.0のhostへv0.1.0の配布kernelを組み合わせる構成は検証していない。
  stdin入力を伴うrunはminor 1以上のkernelでだけ成立し、古いkernelでは起動前に型付きerrorで失敗する。

v0.1.0のCLI構文と終了codeは変えていない。
`run`のflag、`image build`、`image list`、`image inspect`、`help`、`--version`はv0.1.0と同じ形で動く。

## 互換な追加

### CLI

- `run --detach`、`ps`、`stop`。detached runはinstance id `i-<pid>`を1行で返し、`ps`と`stop`がstate fileを介して観測と回収を行う。
- `run --memory`と`run --cpus`。QEMUのmemory量とvCPU数を128から8192 MiB、1から8の範囲で指定できる。
- `doctor`。QEMU version、kernel file、store rootを診断し、失敗時は終了code 1で終わる。
- `image import`、`image export`、`image remove`、`image prune`。
- `image export-oci`、`image import-oci`、`image pull-oci`。OCI Image Layoutとの往復と、匿名digest pinによるregistry pullを追加した。

### runtime

- 標準出力と標準エラー出力の逐次転送。合計1 MiBの上限はv0.1.0のまま維持している。
- 非TTYの標準入力転送。4096 byte単位の`Stdin` frameでguestへ届け、EOFを明示的に伝える。
- SIGINTとSIGTERMの転送と後始末の統一。中断されたrunは2秒のgraceののちSIGKILLで回収し、終了code 125で終わる。

### 配布と検証

- 配布archiveへGitHub artifact attestationによる署名済みprovenanceを付けた。
- MiniBundle parserとUART decoderの決定性fuzz harnessを追加し、固定seedのbounded smokeをrelease gateに含めた。
- E2Eへ反復と中断のcleanup stress節、公開commandのcli surface passを追加した。
- ABI v1.0のbundleを現行hostが受理することを、check-inしたfixtureとdigest pinで検証する。

## 契約の固定

v1.0.0で安定化の対象とする契約は、MiniBundle format、Guest ABI、CLI構文と終了code、instance state schema、MiniBundleとOCIの対応である。
`minicontainer-*`のRust crateは公開契約に含めず、利用者が依存してよい公開面は`minictr` binaryだけである。
サポート対象は最新releaseのみであり、旧release系統へのbackportは行わない。

## 必要環境

- Rust 1.98.0、`riscv64gc-unknown-none-elf` target、QEMU 8.2.0以上、Git。
- Apple Silicon搭載macOSまたはUbuntu 24.04。
- Guest ABIは`minios-abi-v0.2.0`、実行kernelはminiOSの固定revision `4865f9be97a6cdcd77c71e36b1ba426b49bd73d7`からbuildする。

## 検証

- `cargo xtask check-host`で実QEMUを除く17段階を検証する。
- `cargo xtask check`で実QEMU end-to-end検証を含む18段階を検証する。
- Ubuntu CIは`setup`と`check`に加えて配布archiveのsmoke、OCI interop、互換性fixtureを検証し、macOS CIは`check-host`を実行する。

## 制約と非保証

- MiniContainerは本番用のセキュリティー境界ではありません。
- 未信頼コードを扱うマルチテナント環境、guest escapeの防止、Linuxアプリケーション互換、ネットワーク、永続ボリューム、Docker API互換は保証しない。
- manifest v2と`ProcExit` frameによる複数image実行は、frame集合に含まれるが現行runtimeでは受理しない。
- `SIGKILL`による強制終了では後始末を保証しない。
- Windowsには対応しない。
- 詳細は[互換性と移行の方針](compatibility.md#v100が保証しない範囲)と[脅威モデル](threat-model.md)を参照する。
